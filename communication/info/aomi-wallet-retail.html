01 The blocker — and what's already built

The chat UI is a sprint.
The safety layer is the year.

Nobody needs convincing on the surface itself — Coinbase put agents in the Base app, OKX shipped an agentic wallet, Kraken is rebuilding its consumer app around them, Robinhood extended agentic trading to crypto, MetaMask shipped a developer-facing agent wallet. Users already push billions through plain text boxes. What slips the roadmap item is everything underneath the chat UI.

/01 · the published bar

Simulation, threat scanning, spend caps, protocol allowlists, insured signing — the checklist the first movers set is now the minimum. Ship less and the security review vetoes it; ship it all and it's a platform program.

/02 · the build underneath

Forked-state simulation infrastructure, a policy engine, multi-chain broadcast across EVM + SVM, model evals — 12–18 months of work competing with everything else on the roadmap.

/03 · the blast radius

One hallucinated transaction or one injection headline retires the feature. Chat input is a new, drainer-shaped attack surface — language must never be able to cause an unverified state change.

03 Capability breakdown

The capability set, in detail.

The architecture, the pipeline it enforces, the controls around it, and the terms. Nothing here is bolted on — each is a property of a runtime built directly on a full node that forks every chain in ~200ms, EVM + SVM.

3.1

System architecture

one harness · every chain, forked
Multi-threaded async execution
Agent threads run server-side, so work continues after the app is closed — background strategies, limit / stop orders, copy-trading a target wallet, scheduled DCA and rebalances, and liquidation guards that fire on their own. Surface area a swap screen cannot express.
Access control
Provider-native key delegation — Para, wagmi connectors, or an in-house adapter — with machine auth solved: an agent signs only under a scoped, revocable policy (value caps, human-sync or autonomous). Keys never leave the user's own wallet.
3.2

Execution pipeline

build · simulate · sign · broadcast
Step 01

Build

Intent parses into the exact transaction — routed through the aggregators already integrated, batched into a single operation.

intent → exact tx
Step 02

Simulate

Executed against forked, live chain state to prove the real outcome — fill, slippage, balance changes — before anything is signed.

forked state · ~200ms
Step 03

Sign

Signed by the user's own wallet through the product's existing signer — per-transaction approval, or scoped delegation within caps.

existing signer · unchanged
Step 04

Broadcast

Confirmed onchain with account abstraction and Solana Jito built in — no execution infrastructure for the product team to run.

AA + Solana Jito
Quote = outcome. What the surface displays is what the chain settles — the property that makes chat over irreversible transactions shippable.
3.3

Control framework

the policy, enforced
Policy as configuration

Spend caps, venue allowlists, per-session limits, per-wallet rules — defined by the product, enforced on every action. Per-transaction human approval by default; scoped delegation where the product allows it.

spend capsallowlistssession limits
Kill switch & injection defense

Chat input is untrusted by design: language can only propose; the pipeline verifies. A failed simulation or out-of-policy proposal stops before signature. Halt an agent instantly, revoke a grant instantly.

instant haltinstant revoke
Custody model

Non-custodial by construction. The harness consumes the existing signer interface — an in-house adapter, Para, or wagmi connectors — and key material never moves. The self-custody story the product sells stays exactly true.

keys never movesigner-agnostic
Oversight & audit

Per-app telemetry on every turn; each executed transaction traceable to the user intent that authorized it. Execution-only by construction — no recommendations, no discretion — with logs built for compliance review.

full audit trailexecution-only

The invariant: aomi can compose and simulate any transaction, but can only ever propose it. Authority to move value remains with the user's key and the product's policy — the property that keeps a conversational surface on the tooling side of the advice line.
